## Findings

- **468 entries:** keep their current classification.

- **6 entries:** tentative recommendations to move; their autonomous curricula sit closer to the definition's boundary.
- **18 entries:** mixed mechanisms or a boundary that the definitions do not cleanly resolve. Four explicitly contain both exploratory acquisition and direct optimization; fourteen remain interpretive boundary cases.

## Interpretation of the definitions

The definitions used were:

- **Discovery:** To explore and discover new concepts and skills beyond the immediate task.
- **Direct optimization:** To improve the task metric directly.

I classified the purpose of the improvement phase. Discovery includes a deliberate exploratory learning agenda: investigating an unfamiliar environment or tool before assigned tasks, or independently choosing new challenges that extend capabilities. Direct optimization includes task-feedback-driven parameter changes, prompt and harness repairs, and memory or tool updates serving assigned problems.

Both can use rewards, verifiers, and task-specific final evaluation. The presence of a metric does not distinguish them. Reusable skills, transfer to new tasks, an outer optimization loop, generated training data, or a method's use of the word “discovery” also do not establish Discovery by themselves. Scientific discovery can be the assigned task; improving that task's solver can still be Direct optimization.

The main unresolved boundary is open-ended agent-design search: exploration of novel designs and direct selection by task scores often coexist. The definitions do not specify how far a search must depart from the current objective to count as a broader conceptual discovery. DGM, ADAS, and related systems should therefore not be presented as unambiguous examples without stating which phase or purpose is being classified.

## Host-dependent module

[ANCHOR](https://arxiv.org/pdf/2606.06114v3#page=3): ANCHOR supplies phase-level supervision to R-Zero and AZR; its safety and error-control mechanism does not independently specify a discovery or direct-optimization learning agenda. Its evaluated hosts are R-Zero and Absolute Zero Reasoner; classify the host learning loop separately from the supervision mechanism.

## Important distinctions from the review

- **SEAL and MASS:** synthetic data and meta-learning serve a supplied target task. Their ability to create edits or examples does not itself make the purpose Discovery.
- **TTCS and GASP:** curricula are centered on supplied target questions or goalpost problems. These differ from independently choosing a broader learning agenda.
- **AgentEvolver, EXIF, RSIAgent, and STE:** exploration generates knowledge or practice before downstream execution, supporting Discovery.
- **OpenSkill:** the initial abstract-level candidate move was rejected after checking the methods. It builds a skill set for each supplied target-task prompt and refines it using virtual tests, so it stays Direct optimization.
- **Agentic Robot Skill Discovery:** new skills are developed to repair execution of a supplied robot task; “skill discovery” in the title is not decisive.
- **Prism, SkillX, APEX, and HexMachina:** explicit exploration and direct improvement mechanisms make a single paper-level label incomplete.

Close calls:

- **ENPIRE:** a frozen coding agent retrains the robot policy that does the task. It stays in, matching SIA, where a feedback agent updates the task agent's weights.
- **JIT-Agent:** training updates a harness generator while the executor stays frozen. Parametric follows ScoreFlow and SkillOS; EASE, also a trained curator, sits in Non-parametric.
- **DarwinX:** it keeps an archive and merges specialists like Mendel Gödel Machine, but a child steers the search only with a net gain on the benchmark's verifier, so it is Direct optimization.
- **Ouroboros:** one lineage, with changes approved by a review panel rather than a score. The documented changes are repairs, and evolution was off for every benchmark run.
- **The Station:** agents choose directions and pose new questions, but each instance serves one assigned problem and its evaluator, as in Dream-RSI.
- **RLSVR:** the math variant writes questions from corpus text, as SPICE does, but the main loop improves supplied target tasks, as SPC does.
- **EnvHarness:** each environment is tailored to a supplied task, as in TTCS and GASP. The main results use a skill bank, so it is Non-parametric; a secondary GRPO run would be Parametric.
- **CrossFit:** the paper (False Frontiers) diagnoses Dr. Zero's loop and changes how proposals are scored, so it takes Dr. Zero's Discovery placement.
- **Self-Play Pretraining:** the improved model is a byte-level predictor trained from scratch, placed like R-Zero's separate challenger and solver.
- **Prime Agent and Continual Harness:** Prime Agent builds on Continual Harness (same first author). Both are listed because only Continual Harness also trains weights.
- **Trusting Trust:** Discovery is an editorial placement consistent with DGM and Hyperagents; their design-search versus benchmark-optimization boundary remains interpretive. The successful DGM attack required a modified diagnosis prompt, while Hyperagents needed no substantial internal modification.

Left out: [autoresearch](https://github.com/karpathy/autoresearch). The agent edits `train.py` to lower a separately trained small GPT's validation loss; its own weights and instructions do not change.
